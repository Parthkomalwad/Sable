# Phase 7 gate runs, 2026-09-29

Five runs of `scripts/gate_phase7.py` in the playground against `openai/gpt-4o-mini`.

## Run 1: 4 PASS, 2 FAIL, 1 UNTESTED

- **Learn and recall: FAIL.** In session 1 the model kept calling `fs.search` and
  `fs.tree` on `/etc/myapp`. Those tools only work inside the working
  directory, and their error did not say what to use instead, so the model
  handed off and no fact was saved. Fixed: the error now names the way out
  (a shell command such as `cat /etc/app.conf`), and an absolute glob gets the
  same hint.
- **/palace why: UNTESTED**, because there was no learned fact to inspect.
- **/remember and /forget: FAIL, harness bug.** The check looked for
  "Tuesdays" in the `/palace find` output, which includes the echoed command.
  It now checks for the "nothing matches" line.

## Run 2: 6 PASS, 1 FAIL

Session 1 now read the config and saved the fact. In session 2 the model knew
the answer but proposed `ls /var/log/myapp` to check first. The memory header
said "verify before acting on them", and the model read answering as acting.
Reworded: a question the notes answer can be answered from them; checking is
for before changing something.

## Run 3: 6 PASS, 1 FAIL

Same behaviour: gpt-4o-mini re-checked with `test -d /var/log/myapp`. The rule
lived only in the system prompt. Fixed: one plain instruction now sits right
after the notes, where a small model reads it last.

## Run 4: 7 PASS

Session 2 answered from memory with no commands, but it also saved the same
fact again in new words, a near-duplicate. The instruction after the notes
now also says not to list them again as facts.
