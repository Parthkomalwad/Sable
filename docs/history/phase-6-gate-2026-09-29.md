# Phase 6 gate runs, 2026-09-29

Three runs of `scripts/gate_phase6.py` in the playground against `openai/gpt-4o-mini`,
with Node 18 and `@modelcontextprotocol/server-filesystem` added to the image.

## Run 1: 4 PASS, 2 FAIL

- **Filesystem goal: FAIL.** The server was added as `fs`, so its tools were
  `mcp.fs.*` next to the builtin `fs.*`, and the model called the builtin
  `fs.tree`, which is confined to the working directory. Two changes: the gate
  names the server `files`, and `registry.describe` now lists MCP tools under
  their own heading, telling the model to use a server's tools when the user
  names it.
- **Elicitation: FAIL.** The mock server never listed its `ask` tool, and the
  model wrote `mcp.mock.t0()` as a shell command. `tool_as_command` cut the
  name at the first space only, so the parenthesised form reached bash.
  Fixed: it cuts at a space or `(`, and the mock lists `ask` in its
  input-required mode.

## Run 2: 4 PASS, 2 FAIL

- **Filesystem goal: FAIL** again: the model still chose the builtin `fs.tree`
  (the prompt heading was not in yet).
- **Elicitation: stopped at the typed `YES`.** The tool call was caught and
  previewed correctly, then asked for `YES`, because MCP tools are confirm
  tier and confirm means a typed YES. The harness did not answer it. The
  harness now does.

## Run 3: 6 PASS

Findings to act on later, not gate failures:

- The model called `mcp.files.list_directory` and answered "15 markdown
  files"; `/app/docs` has 12. The gate checks that the MCP path works, not
  the model's arithmetic.
- Every MCP call asks for a preview and then a typed `YES`, the same as
  `rm -rf`. That is heavy for read-only tools; `/mcp trust` is the way out
  today. A lighter confirm for tools could be worth it.
