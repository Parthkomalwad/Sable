# Phase 5 gate runs, 2026-09-28

Three runs of `scripts/gate_phase5.py` in the playground against `openai/gpt-4o-mini`.
Only run 3 is a clean result; runs 1 and 2 are recorded because they found real problems.

## Run 1: harness crash, no results

The ntfy line closed its HTTP client and then read the topic again
(`RuntimeError: Cannot send a request, as the client has been closed`). Only the
last 15 lines of output were kept, so the per-line results were lost. Fixed in
the script; nothing to say about Sable from this run.

## Run 2: 2 PASS, 3 FAIL

| Gate line | Result |
|---|---|
| /schedule heartbeat, >= 2 lines | PASS |
| confirm-tier job waits in /inbox, approve runs it once | PASS |
| /watch add disk / 1 fires once | FAIL |
| kill sabled mid-job, restart, lost, schedules resume | FAIL |
| ntfy job push and phone approval | FAIL |

- **Watcher: a harness mistake.** Docker Desktop's `/` is 0.48% used, so a 1%
  limit is never crossed. Reproduced alone: the watcher checked and stored
  state `ok`. The gate now uses 0.01%.
- **Kill/restart and ntfy: a real defect.** Jobs ran inline in the daemon
  tick, so one long job (the gate's `sleep 50`) held up schedules, watchers
  and pushes. The run was marked `lost` correctly, but no next run and no push
  appeared in the window. Fixed: daemon jobs and resumed runs now run in their
  own thread on their own connection (`jobs._call`, `background=True`); the
  run row is written before the call returns, so the not-twice check still
  sees it. One test added. Reproduced in isolation the restart itself was
  fine (next run 34 s after restart); the exact stall sequence in the full
  run was not pinned down beyond the inline jobs.
