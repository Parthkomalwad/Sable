# Phase 8 gate runs, 2026-09-29

Seven runs of `scripts/gate_phase8.py` in the playground against
`openai/gpt-4o-mini`, with `--cap-add=SYS_ADMIN --cap-add=NET_ADMIN` (bwrap
needs NET_ADMIN to make a private network as root). The first three lines go
through the model. The last three drive the real code with no model.

## Run 1: 2 PASS, 3 FAIL, 1 UNTESTED

- **Graph: the harness was wrong, the feature worked.** The graph rendered with
  three lanes and a join, and the reviewer answered "concerns": the join lane
  could not write `/tmp/join.txt`, because sub-agents may only write in their
  workspace. The check looked for words the tree does not use.
- **Rehearsal: the lines were not isolated.** The model answered "the file
  system is read-only" without running anything, carried over from the
  previous session's saved context. The palace was empty.
- **Signed skills: a real gap.** Signing needs a key in the keyring, and a
  headless server has no keyring, so nothing could ever be signed. Fixed:
  a 0600 key file at `~/.sable/skill-signing.key` when there is no keyring.

Also found while fixing that: a keep-both merge had dropped the
`@pytest.fixture` line of `_no_real_snapshots` in `tests/unit/conftest.py`, so
unit tests were writing undo snapshots into the real `~/.sable`. Restored. A
scan of every Python file found no other joined definitions. The test junk it
had left in `~/.sable/snapshots` was removed.

## Run 2 (rehearsal and undo alone): 1 FAIL, 1 UNTESTED

The model listed its own working directory, gave up, and saved "The current
directory is empty" as a fact. The line tests rehearsal, not planning, so the
goal now names its three commands exactly. A junk fact about a temp directory
is a finding for memory hygiene.

## Run 3: 3 PASS, 2 FAIL, 1 UNTESTED

The router asked `[b]ash or [a]gentic?` for the half-English, half-command
line and the harness did not answer. The graph lanes took longer than the
harness waited.

## Run 4: 3 PASS, 3 FAIL

- **Rehearsal: a real gap.** The model sent the three changes as one command
  chained with `&&` instead of a plan, so nothing was rehearsed. The reviewer
  said pass. Fixed: a chain with two or more state-changing parts counts as a
  plan and is rehearsed.
- **Undo:** `/undo` alone looks at the current session only, and the gate
  runs in a new one. The gate now undoes by id from `/undo list`, which is the
  across-sessions path.

## Run 5: 5 PASS, 1 FAIL

One graph lane stayed "running" past the harness's wait. Not diagnosed; the
harness now dumps the tasks table and each lane's tmux pane.

## Run 6 (graph alone): PASS

All three lanes completed. The reviewer answered "concerns": the join's output
did not show the counts it wrote.
