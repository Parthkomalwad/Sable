- **Nightly palace consolidation, rules only (Phase 7 Task 3, C3).** `sable/memory/consolidate.py` expires facts past `valid_to`, drops episodic facts older than 30 days, merges near-duplicates in a room (token overlap of 0.8 or more; the older fact keeps its text and gains every source) and promotes an episodic fact seen in two sessions to semantic. No model is called; a second run changes nothing. Each change is published as `palace.consolidated` and logged. The daemon runs it once a day at the new `maintenance_time` config key (local HH:MM, default 02:30), and a restart in that minute does not run it twice. 8 tests.
- **Agents recall and record facts (Phase 7 Task 1, C6 C1).** The orchestrator and every worker get the palace's facts for the goal as one block of about 800 tokens, placed right after the goal, framed as untrusted notes that grant no permissions, with facts from a tainted run labelled per line. A `done` may carry up to five `facts` (`user:` or `repos/<name>:` picks the room), saved episodic with session, goal and the commands that ran, untrusted when the agent was tainted, each shown as a dim "remembered" line. A goal the notes already answer finishes from memory without running a command. A broken palace never breaks a goal. 17 tests.
- **The memory palace store (Phase 7 Task 0, C6).** `sable/memory/palace.py` keeps what Sable learns about a server as one markdown file per fact under `~/.sable/palace/<room>/`, with an FTS5 index in the session database that `reindex()` rebuilds from the files. Rooms are `server`, `user`, `incidents` and `repos/<name>`; tiers are episodic and semantic; every fact keeps its sources. The same fact twice is one file with both sources. Secrets are redacted before storage, expired facts are skipped, bad room names are refused. 14 tests.
- **`sable export`, `sable import`, `sable sync` (Phase 7 Task 5, I8).** The portable set is a fixed allowlist: `~/skills`, `~/.sable/palace`, `~/.sable/policy.toml`, `~/.sable/hooks`; never the keyring, the database, logs, `state/` or `config.json`. `export [file]` writes a tar.gz with a `MANIFEST.json` (version, host, time, sha256 per file), skips symlinks with a note, and refuses (naming the files) if any file holds a structured credential. `import <file> [--yes]` checks every member before writing anything (regular files only, no absolute paths or `..`, only the allowed roots, hashes must match), stages with tarfile's `data` filter where available, shows add/overwrite counts, asks, backs up overwritten files to `~/.sable/import-backup-<ts>/`, refuses to write through an existing symlink, and reindexes the palace. `sync <git-remote>` keeps the same set in a git work tree at `~/.sable/sync`: commit, `pull --rebase`, push, never forced; a conflict stops and is reported; pulled files go back out under the import rules. No new dependencies. 12 tests.

### Added

- **Blocks in scrollback (G2).** Every command the REPL runs, typed or run by the orchestrator, is a numbered block: `#N  <command>` before its output and `exit · duration` after (plus `$cost` for agent commands, whose header is only `#N` in the blast colour because the preview already showed the command). Blocks are stored in a new `blocks` table with the last 200 lines of output, redacted. `/block` lists the last 20; `/block N show|copy|rerun`, where `rerun` goes through `gate()` in the block's cwd. Full-screen programs (vim, htop, less, ssh, or anything that switches to the alternate screen) get only a footer. The separate `exit N` line after a failed typed command is replaced by the footer. See contracts.md §10. 12 tests.

- **The orchestrator's reasoning streams while it thinks (G3).** Once the model's `explanation` starts arriving, the spinner gives way to one dim line that grows in place, truncated to the terminal width, and is cleared before the usual preview. Only the explanation is shown, never raw JSON. The OpenAI, Anthropic and Ollama backends pass each chunk to an optional `on_text` callback through `call_llm`; a backend that cannot stream keeps the spinner exactly as before. Display only: the parse chain still runs on the full text. 14 tests.
- **Palette, themes, ghost text, explain-last-error (G5, G6, K1, K2).** `Ctrl+P` opens a fuzzy palette over builtins, skills, snippets and tasks; Enter runs a builtin that takes no argument and inserts anything else at the prompt. `/theme default|mono|high-contrast` recolours the prompt and the shell's own lines and is saved as `theme` in config.json (old configs load as `default`). `/layout focus|fleet|minimal` resizes the tmux panes, and says so and does nothing outside tmux. Ghost text now comes from history ranked by commands typed in the same directory, then recency, from an in-memory index with a 150 ms budget; the directory for each line is kept in `~/.local/share/agentic-shell/history_cwd` beside the old history file. After a typed command exits non-zero the shell prints `? explain   ! fix` under the block footer: `?` sends the command, exit code and last 40 output lines, redacted, and prints a short explanation; `!` hands a fix request to the orchestrator, so the proposal gets the usual preview and `gate()`.
- **Reading a credential file always needs `YES`.** A model that reads a private key has sent it to its provider, which is the leak. Any command or tool call that names one (`~/.ssh` private keys and `authorized_keys`, `~/.aws/credentials`, `~/.gnupg/`, `.netrc`, `.pgpass`, `.git-credentials`, docker and kube configs, Sable's own config file, `/etc/shadow`, `/etc/sudoers`) is at least `confirm`, from a built-in floor in `policy/privilege.py` beside the `sudo` one, so no policy file can relax it and a sub-agent is refused. `cat` and `fs.read` are covered by the same rule. Public keys and `known_hosts` are not affected. 24 tests.

### Fixed
- **A model answering with two JSON objects in one turn lost the whole turn.** `gpt-4o-mini`, asked for a multi-step goal, emitted a `run` object and a `spawn` object back to back. That is valid JSON followed by more valid JSON, which `json.loads` rejects as `Extra data`, so the turn was discarded and the goal abandoned. One action per turn is the contract, so the first complete object is the answer and anything after it is the model getting ahead of itself: `parse_llm_json` and `runtime.parse_json_action` now fall back to `raw_decode`, which takes that first object and stops. Genuinely broken JSON, a bare list and a truncated object still fail as before, each with a test.
- The orchestrator's system prompt now asks for exactly one object per turn, so the parser fix treats the symptom while the prompt addresses the cause.
- **A parse failure was reported as "LLM unreachable".** That label sent a real user to check a backend that was answering perfectly, and cost a round of debugging in the wrong place. `core/health.py` grows `llm_unparseable`, which says the backend is fine and suggests a stronger model for the role; the orchestrator picks between the two by exception type rather than lumping them together.
- **Natural-language goals never recorded their cost.** Nothing on the orchestrator path wrote a `token_events` row, and that is the table the sidebar, `/stats`, `/history` and `app/budget.py` all read. So a goal that genuinely billed the user's key reported `Cost $0.0000 · Calls 0`, and worse, the daily and session budgets could never trip on orchestrator spend because the rows they count did not exist. The token counts were already in `agent_turns`; they simply never reached the table everything else reads. `_record_cost` now writes one row per turn, tagged `nl_route` and attributed to the session. Found by running a real goal against a real key rather than by any test, which is why 12 now cover it.
- `_record_cost` creates `token_events` if it is missing, the same guard `EventBus` and `ReplayLog` already carry. An orchestrator can run in a process that never constructed `Database`, and a missing table would otherwise be swallowed as a silent zero, which is the exact failure being fixed.
- **The orchestrator described delegating instead of delegating.** Asked for a multi-step goal, `gpt-4o-mini` answered `{"action": "done", "explanation": "...so I'm delegating the task to a sub-agent"}`: it narrated the spawn in the one field that invites prose, and `done` ended the run. No sub-agent, no task row, no tmux window. The prompt listed `spawn` in its schema but never said that `done` terminates, so the model had no reason to think the two were exclusive. `sable/llm/prompts/orchestrator.md` now says so explicitly, and two tests pin the wording so the rule cannot be dropped silently. Diagnosed entirely from `agent_turns`, which is what the Phase 1 replay log was built for.
- `pricing.json` gains `gpt-4.1`, `gpt-4.1-mini`, `gpt-4.1-nano` and `o3-mini`. Only `gpt-4o` and `gpt-4o-mini` were priced, so every other OpenAI model computed to exactly $0.00 and reported it as fact.
- `/skill edit <name>` raised `NameError` on every invocation: the handler read `os.environ` and the module never imported `os`. Nothing caught it because `/skill` had no tests at all, which is the more interesting half of the bug; `tests/unit/test_skill_builtin.py` now covers list, new and edit.
- The spinner verb count was 186 everywhere; it is 187. `docs/vision.md` §2.6's verification command grepped for single-quoted strings, which skipped `"Beboppin'"` because its apostrophe forces double quotes in source. The command now counts with Python.
- `pyproject.toml` ships the new data files. Without the `package-data` globs and an `__init__.py` in `policy/defaults/`, an installed copy would have had no policy file and refused to start.
- The playground image ran Python 3.10 while `pyproject.toml` requires >=3.11 and CI tests 3.11/3.12, so every local test ran against a Python the project does not claim to support and could diverge from CI in either direction. `docker/Dockerfile.playground` moves to `ubuntu:24.04` (Python 3.12). Suite is unchanged across the bump: 338 unit and 76 integration on both.
- `/task new` raised `NameError` instead of spawning. The Phase 0.5 split moved `_get_recent_turns` into `app/builtins/task.py` but left the `_active_turns` global it read behind in the REPL. The handler already received the turns list as an argument, so it now uses that; covered by `tests/unit/test_task_builtin.py`, whose three `/task new` tests all fail against the broken version.
- **The playground had no telemetry sidebar or tasks bar.** `docker/playground-entry.sh` launched a single bare tmux pane, while `install.sh` builds three on a real machine, so the Phase 0 gate item "sidebar visible" could not be met. It now creates the same layout: shell, a 48-column telemetry sidebar and a tasks bar. Panes are sized by a `client-attached` / `client-resized` hook, because tmux resizes the session to the attaching client and would otherwise squeeze splits made beforehand; the sidebar collapses under 120 columns and returns above it. The hook addresses panes by id, since tmux renumbers indices as panes are created.
- **The SSH bypass did not fire for `ssh host cmd`, `scp` or `rsync`.** sshd runs the login shell as `sable -c "<command>"` and leaves `SSH_ORIGINAL_COMMAND` unset; that variable is only populated behind `ForceCommand` or an `authorized_keys` `command=`. The guard checked the env var alone, so a non-interactive SSH command landed in the interactive REPL instead of bash. It now takes the command from `argv` when invoked as `-c`, falling back to the env var. Found by running the Phase 0 gate in the playground, covered by `tests/unit/test_ssh_bypass.py` (6 of its 8 tests fail against the old guard).

### Changed
- **Phase 1: `sable/` has zero bare exception handlers,** down from 72 at the start of the phase. Every `except Exception` and every bare `except:` now names what the code underneath can actually raise: `sqlite3.Error` on database reads, `OSError` plus `subprocess.SubprocessError` wherever a process is spawned, `json.JSONDecodeError` on config and payload parses, `termios.error` where a pty is put into raw mode, `ImportError` where an optional dependency is reached for. Each keeps a comment saying why swallowing is right *there*, since the answer differs per site. `structure.md` §4.7 bans the pattern because unexplained silence is the worst failure mode this category of tool has; the lint in CI can become blocking now.
- The sweep surfaced a real bug it was meant to surface. `tests/unit/test_skill_crystalliser.py` constructed an `LLMResponse` without its three required positional fields, raising `TypeError`; the crystalliser's old `except Exception` swallowed it, so the test passed by silently taking the generation-failed branch and asserting only on the prompt it had already captured. With the handler narrowed, the error is visible and the test is fixed.
- **Two layering violations introduced in PR4 are gone.** `core/events/replay.py` imported `policy` for `strip_secrets`, and `core/health.py` imported `agents` for the bwrap probe: both are `core` reaching upward, the worst direction in the rule, and the pre-existing xfail was masking them. `ReplayLog` now takes the redactor as an argument (`policy/engine.py` grows `redact_text`, and the agents that record turns supply it), and the bwrap probe moved into `core/health.py` with `Sandbox` calling it, so the sandbox and the degraded-mode banner cannot disagree about what is available.
- `TaskAgent` and `TaskManager` accept their collaborators (`TaskMemory`, `TaskSkillLoader`) by injection, constructed by the composition root. Both keep a deferred-import fallback so existing callers and tests work unchanged, which means the three `agents -> memory/skills` edges are reduced but not yet eliminated; `test_layering.py`'s xfail stays until the fallbacks can go.
- **The production image had rotted unnoticed.** `docker/Dockerfile` was `ubuntu:22.04` (Python 3.10, below the `>=3.11` this project requires) and registered a login shell of `python3 -m shell.main`, the compat shim that `structure.md` §5 step 7 deletes one release out: the image would have stopped booting the day that happened. It moves to `ubuntu:24.04`, invokes `sable.app.main`, and no longer copies `shell/` at all. `install.sh` keeps its `shell.*` strings deliberately, because those are what already-installed machines invoke and `test_inplace_upgrade.py` covers them. CI now builds this image and checks it starts, which is why the drift went unnoticed for so long.
- Docs said `/task <name> events`; every subcommand parses `<sub> <name>`, as `attach`, `pause`, `stats` and the rest have always done. Six references across four docs corrected to match the code rather than changing nine shipped subcommands to match the docs.
- `layout.py` no longer passes `--no-tmux`: nothing parsed it, and it was redundant anyway, since `create_session()` already returns early when `$TMUX` is set.
- **Phase 1: every caught exception in `sable/agents/` is typed.** All 22 bare `except Exception` there are gone: 8 deleted along with the duplicated pty and asyncio loops, 14 replaced with what each site can actually raise (`LibTmuxException` for tmux traversal, `OSError` plus `subprocess.SubprocessError` where a process is spawned, `httpx.HTTPError` plus `runtime.AgentError` plus `ValueError` around an LLM call). Each keeps a comment saying why swallowing is right *there*, since the answer differs: an unwritable `status.md` is a lost mirror and the bus still has the step, while an unparseable config means a worker with no terminal to ask on must run on defaults. Anything outside those sets is now a bug in Sable and surfaces as a traceback instead of silence. `sable/` drops from 72 bare handlers to 45; `agents/` is at zero.
- `manager.back()` caught `(IndexError, Exception)`, which is just `Exception`: the first is a subclass of the second and could never match alone. Found while typing the handlers.
- Nothing in `sable/agents/` names `LibTmuxException` any more. Typing the tmux handlers against libtmux's own exception base meant importing `libtmux.exc`, and a large part of the test suite replaces `libtmux` in `sys.modules` with a `MagicMock`, where resolving a *submodule* of a mock raises `ModuleNotFoundError`. That broke all 7 tests in `test_orchestrator_spawn.py` and all 12 in `test_reconcile.py`. Deferring the import into the function did not help: the mock is installed for the whole test body, so the failure moves from import time to call time and no further. `orchestrator.py`, `reconcile.py` and `manager.py` now catch what the failure actually arrives as, since libtmux shells out to tmux: `OSError` and `subprocess.SubprocessError` for a missing or dead server, `AttributeError` and `KeyError` for its parsing of unexpected tmux output. A tmux error deriving straight from `Exception` escapes to the caller, which is correct: it means the manager is broken, not that one spawn was refused.
- **Phase 1: sub-agent progress moves onto the event bus.** The orchestrator read `status.md` and `result.md` on a 3 second poll and deleted `result.md` once consumed, which lost the result outright if it died between the read and the unlink. Workers now publish `started` / `status` / `completed` / `failed` / `lost` to `agent_events`, and the orchestrator drains them through a cursor it owns. Measured cross-process delivery is 0.11s against the old 3 second poll, and exactly-once delivery no longer depends on a destructive read.
- The cursor starts at the bus head rather than zero, so re-running a goal under the same slug cannot fold a previous run's results into the new run's context.
- `status.md` and `result.md` are still written, now purely as human-readable mirrors: nothing reads them back. `_write_result_summary()` returns the summary so it can travel on the bus as the `completed` payload.
